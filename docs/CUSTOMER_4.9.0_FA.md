# نسخهٔ 4.9.0 — بهبود منوی مشتری

پایهٔ این نسخه بستهٔ 4.8.0 ادمین است. تمام فایل‌های اجرایی ادمین، backend، SQL و تصاویر اصلی با بستهٔ ورودی یکسان‌اند. تغییرات این مرحله در منوی مشتری، کش، آزمون‌ها و مستندات هستند. این بسته روی سرور واقعی منتشر نشده است.

## طراحی و امکانات

- بخش مرور منو با جست‌وجو، تعداد نتایج، دسته‌بندی، علاقه‌مندی‌ها، ترتیب قیمت و پاک‌کردن فیلترها.
- جست‌وجو در نام، توضیح و دستهٔ محصول با متن زبان انتخاب‌شده؛ یکسان‌سازی حروف فارسی/عربی، اعراب و برخی تفاوت‌های ترکی.
- مرتب‌سازی قیمت در هر دسته؛ محصولات بدون قیمت در انتهای همان دسته قرار می‌گیرند.
- ذخیرهٔ علاقه‌مندی‌ها در همین مرورگر، جدا برای هر شناسهٔ رستوران. این قابلیت حساب کاربری یا همگام‌سازی بین دستگاه‌ها ندارد. در صورت مسدودبودن ذخیره‌سازی، انتخاب تا پایان همان صفحه کار می‌کند.
- کارت‌های شبکه‌ای سه‌ستونه در دسکتاپ و دو‌ستونه در موبایل، تصاویر با نسبت یکسان، توضیحات کوتاه، دکمهٔ علاقه‌مندی و حالت فوکوس مشخص؛ هویت تیره و طلایی حفظ شده است.
- کنترل‌ها و پیام‌های جدید به فارسی، انگلیسی، ترکی و عربی؛ جهت RTL/LTR و نام کامل زبان‌ها.
- پنجرهٔ جزئیات قابل پیمایش، فوکوس صفحه‌کلید، خروج با Escape، غیرفعال‌شدن محتوای پشت پنجره و بازگرداندن فوکوس.
- حالت‌های واضح برای نتیجهٔ خالی، نبود علاقه‌مندی، منوی خالی، بارگذاری، حالت آزمایشی و خطای ارتباط.

## رفع اشکال و صحت داده

- دادهٔ نمونهٔ محلی هنگام انتظار برای API به‌عنوان منوی واقعی نمایش داده نمی‌شود.
- پاسخ خالی معتبر سرور، خالی باقی می‌ماند؛ داده‌های محلی ادمین جای آن را نمی‌گیرند.
- محصولات غیرفعال، محصولات دستهٔ غیرفعال و محصولات بدون دستهٔ معتبر از تمام بخش‌های عمومی حذف می‌شوند.
- در خطای شبکه یا خطای 5xx، آخرین پاسخ عمومی معتبرِ همین رستوران، فقط تا ۲۴ ساعت و همراه پیام عدم به‌روزبودن نمایش داده می‌شود. کش خصوصی ادمین استفاده نمی‌شود. کش منقضی، شناسهٔ دیگر و پاسخ JSON با وضعیت 404 به حالت خطا می‌روند.
- میزبانی ایستای بدون API که 404 غیر JSON برمی‌گرداند، همچنان حالت آزمایشی است و در منو برچسب دارد. برای انتشار واقعی، مسیر و پاسخ خطای API باید درست تنظیم شوند.
- تغییر localStorage پنل آزمایشی نمی‌تواند منوی متصل به API را بازنویسی کند. همگام‌سازی بین تب‌های آزمایشی حفظ شده است.
- امتیاز صفر به پنج ستاره تبدیل نمی‌شود. برای قیمت نامشخص متن مناسب نمایش داده می‌شود.
- عنوان و توضیحات صفحه از اطلاعات جاری رستوران به‌روز می‌شوند.
- لینک مستقیم محصول با پاسخ دیرهنگام API کار می‌کند؛ پارامترهای URL حفظ می‌شوند و بستن پنجره hash محصول را پاک می‌کند.
- service worker نسخه‌بندی شده است و درخواست‌های API و ادمین را کش نمی‌کند. این تغییر به معنی تأیید کامل عملکرد آفلاین PWA نیست.

## آزمون‌های انجام‌شده

- `npm run qa`: ممیزی ایستا با صفر خطا و صفر هشدار، بررسی نحو و ۲۲ تست واحد موفق.
- `npm run qa:customer`: ۱۳ سناریوی Chromium موفق شامل جست‌وجو، دسته، ترتیب قیمت، علاقه‌مندی و ماندگاری آن، پنجره و فوکوس، تغییر داده بین تب‌ها، لینک مستقیم با تأخیر ۲٫۳ ثانیه، پنهان‌بودن محصولات نامعتبر، escape متن HTML، تفکیک دادهٔ عمومی و محلی، کش و خطا، منوی خالی و ذخیره‌سازی مسدود.
- چیدمان مشتری در چهار زبان × سه عرض ۳۲۰، ۳۹۰ و ۱۴۴۰ بررسی شد: جهت درست، نبود اسکرول افقی صفحه و حداقل عرض قابل‌خواندن کارت‌ها. نمونه تصاویر نیز بازبینی شدند؛ اشکال فشرده‌شدن کارت‌های موبایل در همین بازبینی پیدا و رفع شد.
- `npm run qa:browser`: ۱۶ سناریوی ادمین دوباره موفق؛ ۴۸ ترکیب صفحه/زبان/عرض نیز بررسی شد.
- در سناریوهای اجراشده خطای JavaScript مدیریت‌نشده ثبت نشد.
- نتایج JSON و تصاویر در `docs/qa/` قرار دارند. پاسخ‌های سرور در آزمون مرورگر شبیه‌سازی شده‌اند و service worker در آن آزمون‌ها مسدود بوده است.

## اجرای آزمون مرورگر

یک پیش‌نمایش ایستا از ریشهٔ پروژه اجرا کنید؛ مثلاً `python3 -m http.server 8765`. Playwright و Chromium را در محیط آزمون نصب کنید، سپس در ترمینال دیگر:

```sh
ADMIN_TEST_URL=http://127.0.0.1:8765 npm run qa:customer
ADMIN_TEST_URL=http://127.0.0.1:8765 npm run qa:browser
```

در صورت نیاز مسیر Chromium را با `CHROMIUM_EXECUTABLE_PATH` بدهید. این آزمون‌ها برای محیط محلی و دادهٔ آزمایشی طراحی شده‌اند؛ به آدرس تولید اشاره نکنید.

## مرحلهٔ بعد پیشنهادی

۱. اجرای مسیر کامل ورود ادمین، ذخیرهٔ محصول و نمایش مشتری با PostgreSQL واقعی؛ سپس بررسی آپلود تصویر و سرویس ترجمهٔ واقعی.
۲. افزودن جریان پیش‌نویس/پیش‌نمایش/انتشار و کنترل ویرایش هم‌زمان برای جلوگیری از انتشار ناخواسته یا بازنویسی تغییرات دیگران.
۳. پس از تثبیت داده و انتشار، افزودن اطلاعات آلرژن و رژیم غذایی در مدل داده و رابط ادمین و مشتری، بر اساس نیاز واقعی رستوران.

این نسخه تأیید امنیت تولید یا تست Safari/Firefox نیست؛ استقرار، پایگاه داده و سرویس ترجمهٔ واقعی در این مرحله آزموده نشده‌اند.
