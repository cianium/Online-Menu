# نسخه 4.8.0 — توسعه و دیباگ پنل ادمین

## محدوده این نسخه

پایه: بستهٔ 4.7.1 بررسی‌شده در همین گفتگو. این مرحله روی پنل ادمین تمرکز دارد. کد منوی مشتری، تصاویر اصلی، SQL و منطق backend تغییر نکرده‌اند. هیچ استقرار عمومی انجام نشده است.

## اصلاحات فنی

- بارگذاری از سرور اکنون آرایه‌های خالی محصولات و دسته‌ها را معتبر می‌داند. دادهٔ نمونهٔ مرورگر دیگر خودکار به سرور فرستاده نمی‌شود.
- قطع ارتباط یا پاسخ نامعتبر سرور، صفحهٔ خطا و امکان تلاش دوباره نشان می‌دهد؛ پنل به حالت آزمایشی قابل‌ویرایش تبدیل نمی‌شود. حالت آزمایشی برای `file://` و میزبانی ایستایی که API آن 404 غیر JSON برمی‌گرداند باقی است.
- در حالت سرور، موفقیت ذخیره پس از تأیید API اعلام می‌شود. در شکست قابل‌تشخیص، state قبلی بازمی‌گردد و اطلاعات فرم برای تلاش دوباره باقی می‌ماند.
- دادهٔ سرور دیگر در کلیدهای مشترک نسخهٔ آزمایشی مرورگر ذخیره نمی‌شود.
- کنترل‌های ویرایش هنگام ذخیره موقتاً غیرفعال می‌شوند تا درخواست هم‌زمان از همین صفحه ایجاد نشود.
- بازیابی بکاپ اکنون منتظر ذخیره می‌ماند؛ در شکست، دادهٔ قبلی بازمی‌گردد. فایل بزرگ‌تر از 10 MiB پیش از خواندن رد می‌شود.
- وضعیت «ذخیره‌شده» در تنظیمات فقط پس از موفقیت واقعی به‌روز می‌شود.
- تأیید عملیات در هر بار بازشدن بازنشانی می‌شود؛ فشردن Escape پس از یک تأیید قبلی به معنی تأیید مجدد نیست. متن‌ها چهارزبانه و درخواست‌ها صف‌بندی شده‌اند.
- بستن فرم محصول یا دسته با تغییرات ذخیره‌نشده نیازمند تأیید است. خروج از صفحه هنگام ذخیره یا وجود فرم ویرایش‌شده هشدار می‌دهد.
- URL تصویر برگشتی سرور وارد state می‌شود تا همان تصویر در ذخیرهٔ بعد دوباره آپلود نشود.
- ستاره‌های امتیاز هنگام ارسال snapshot به صفر تبدیل نمی‌شوند. قیمت اعشاری پذیرفته می‌شود و نمایش قیمت ادمین از ارز مشخص‌شده در دادهٔ رستوران پیروی می‌کند.
- منوی کناری بسته در موبایل مخفی و غیرقابل فوکوس است. جابه‌جایی RTL/LTR باعث نمایش گذرای آن نمی‌شود.

## قابلیت‌ها و طراحی

- داشبورد بررسی محتوای محصولات فعال: بدون تصویر، بدون قیمت، بدون توضیح و دستهٔ نامعتبر؛ هر کارت به فیلتر همان موارد وصل است.
- فیلتر کیفیت محتوا در کنار جست‌وجو، دسته، وضعیت و ترتیب نمایش.
- انتخاب موارد نمایش‌داده‌شده و فعال/غیرفعال‌کردن گروهی با تأیید. با تغییر فیلتر، موارد پنهان از انتخاب خارج می‌شوند.
- رونوشت محصول به صورت فرم قابل‌ویرایش، با وضعیت پیش‌فرض غیرفعال؛ ایجاد محصول جدید فقط پس از ذخیره.
- نمایش وضعیت ذخیره/خطا/حالت اتصال، اعلان‌های قابل‌خواندن با فناوری کمکی و نام کامل زبان.
- رنگ‌بندی تیره با تأکید طلایی، کنتراست و فاصله‌گذاری بهتر، کارت‌ها و فرم‌های هماهنگ، وضعیت انتخاب و فوکوس مشخص.
- فیلترهای موبایل باز و بسته می‌شوند و عملیات گروهی تنها هنگام انتخاب محصول ظاهر می‌شود.
- تمام متن‌های جدید رابط در فارسی، انگلیسی، ترکی و عربی تعریف شده‌اند. محتوای واردشدهٔ رستوران در ویرایشگر به زبان اصلی خود باقی می‌ماند؛ ویرایشگر مستقل ترجمه هنوز اضافه نشده است.

## بررسی انجام‌شده

- `npm run qa`: بررسی نحو JavaScript، ممیزی ایستا و مجموعه تست‌های واحد موجود موفق بود؛ ممیزی ایستا صفر خطا و صفر هشدار داشت.
- 16 سناریوی خودکار در Chromium: ایجاد/ویرایش/حذف محصول و دسته، رونوشت، خروج از فرم، لغو تأیید با Escape، شکست ذخیره محلی، شکست بازیابی بکاپ، عملیات گروهی، تنظیمات، بارگذاری دادهٔ خالی سرور، شکست ذخیره و تلاش دوباره، آپلود تصویر و استفاده مجدد از URL، قطع سرویس.
- 48 ترکیب چیدمان: چهار صفحه × چهار زبان × سه عرض 320، 390 و 1440؛ جهت سند درست و بدون اسکرول افقی صفحه.
- صفر خطای JavaScript مدیریت‌نشده در سناریوهای مرورگر. خطاهای ذخیره که عمداً در تست ایجاد شدند، در کنسول ثبت و در رابط مدیریت شدند.
- تصاویر مرورگر و نتیجهٔ سناریوها در `docs/qa/` هستند.

## محدودیت‌ها و کار بعدی

- تست‌های حالت سرور با API شبیه‌سازی‌شده انجام شدند؛ PostgreSQL، احراز هویت واقعی، RBAC، CSRF و جداسازی رستوران‌ها در این مرحله به‌صورت یکپارچه آزمایش نشده‌اند.
- جلوگیری از ذخیرهٔ هم‌زمان در همین صفحه، مشکل ویرایش هم‌زمان چند کارمند/تب را حل نمی‌کند. نسخه‌بندی optimistic concurrency در backend هنوز لازم است.
- اگر ارتباط پس از ثبت واقعی درخواست در سرور قطع شود، رابط از نتیجه قطعی خبر ندارد؛ قبل از تکرار تغییر حساس، دادهٔ سرور باید دوباره بررسی شود.
- محدودیت فعلی backend برای snapshot با صفر دسته باقی است؛ ابتدا یک دسته ایجاد کنید. حذف آخرین دسته یا ذخیرهٔ تنظیمات رستوران کاملاً خالی از این مسیر ممکن است رد شود.
- جریان پیش‌نویس/انتشار/بازگردانی، ویرایشگر ترجمه، مدیریت کارکنان، کتابخانه رسانه، مرتب‌سازی دستی و آمار بازدید هنوز اضافه نشده‌اند.
- نام برخی اجزای قدیمی و لایه‌های CSS قبلی باقی‌اند؛ اجزای جدید در `workspace.js` و `workspace.css` جدا شده‌اند تا بازنویسی گسترده و پرخطر لازم نباشد.
- Firefox، Safari، صفحه‌خوان و موبایل فیزیکی آزمایش نشده‌اند. این نسخه را نباید صرفاً بر اساس این بررسی «آمادهٔ تولید تجاری» دانست.

## اجرا و بازبینی

برای پیش‌نمایش آزمایشی، در پوشهٔ پروژه اجرا کنید:

```sh
python3 -m http.server 8080
```

سپس `http://localhost:8080/admin/` را باز کنید. این حالت، داده‌ها را فقط در مرورگر نگه می‌دارد.

برای اجرای واقعی backend، از `backend/README.md` و `.env.example` استفاده کنید. هیچ رمز، کلید API یا پایگاه دادهٔ آماده‌ای در این خروجی اضافه نشده است.

برای بازاجرای تست مرورگر، Playwright و Chromium را در محیط توسعه نصب کنید، پیش‌نمایش را اجرا کنید و سپس:

```sh
ADMIN_TEST_URL=http://localhost:8080 npm run qa:browser
```

تست‌های مرورگر از API شبیه‌سازی‌شده استفاده می‌کنند و جایگزین تست backend نیستند.
