# مرحله ۱۲ — پنل مدیریت: زیرساخت و عملیات Demo

مبنا: `Online-Menu-customer-polish.zip`، خروجی مرحله ۱۱.۴. این نسخه افزایشی مستقل است؛ شاخه اصلی، Pages و Pull Requestهای GitHub در این مرحله تغییر نکرده‌اند.

## تغییرات

- هدر فشرده حفظ شد؛ دکمه جست‌وجوی سریع که به شکل پویا به هدر بازمی‌گشت به منوی کناری منتقل شد و قابلیت جست‌وجو و Ctrl/Command+K باقی ماند.
- نوار پایین موبایل با ترتیب فیزیکی ثابت چپ به راست: باشگاه مشتریان، محصولات، خانه، دسته‌بندی‌ها، تنظیمات. دسکتاپ منوی کناری را حفظ می‌کند. تغییر صفحه اسکرول را به ابتدا برمی‌گرداند. منوی کناری موبایل هنگام باز بودن پس‌زمینه را inert می‌کند و فوکوس را هنگام بستن برمی‌گرداند.
- داشبورد: کارت‌های عملیاتی و ترتیب بهتر اطلاعات موجود؛ تعداد سفارش در جریان فقط پس از دریافت پاسخ معتبر از API موجود و با برچسب سفارش‌های دریافت‌شده. API تاریخ قطعی پرداخت ندارد، بنابراین نمودار درآمد عدد ساختگی ندارد. امتیاز محلی همان مرورگر پس از تأیید قابل نمایش است. ثبت مجدد امتیاز مشتری تأیید قبلی را پاک می‌کند. هیچ ثبت یا انتشار نظر واقعی انجام نمی‌شود.
- کارت‌های مدیریت محصول و دسته‌بندی: اندازه و چیدمان فشرده‌تر، کنترل‌های لمسی، حفظ ویرایش/حذف/عملیات گروهی. جابه‌جایی دسته‌ها در حالت ترتیب اصلی با دکمه بالا/پایین؛ ترتیب در مدل موجود ذخیره می‌شود و هنگام شکست ذخیره به حالت قبل برمی‌گردد. حذف دسته دارای محصول همچنان مسدود است.
- تنظیمات: محدودیت طول مطابق حدود قبلی، بررسی شماره تلفن و آدرس اجتماعی، رد طرح‌های URL غیر HTTP(S) و URL دارای اطلاعات ورود، اعمال همان بررسی به ورود فایل پشتیبان. این بررسی فقط بخشی از ممیزی امنیت است و جایگزین مجوز سمت سرور نیست.
- باشگاه مشتریان: پیش‌نویس محلی قابل افزودن/ویرایش/حذف/فعال یا غیرفعال‌سازی. محرک تولد، سال نو، اولین خرید، مبلغ خرید و شرط دلخواه؛ پاداش درصدی، ثابت، هدیه یا بدون پاداش؛ متن پیامک و تاریخ انقضا. هیچ موتور اجرا، زمان‌بندی، مشتری واقعی، ارسال پیامک، تخفیف واقعی یا کلید سرویس‌دهنده وجود ندارد. در حالت متصل به سرور CRUD محلی غیرفعال است. داده کاربر با textContent نمایش داده می‌شود؛ داده خراب یا تعارض ذخیره بین تب‌ها موجب توقف و پیام خطا می‌شود. فعال‌سازی پیش‌نویس به معنای فعال شدن ارسال نیست. ذخیره پیش‌نویس‌ها جدا از فایل پشتیبان منو است.
- ترجمه کنترل‌های جدید در fa/en/tr/ar؛ CSS واکنش‌گرا با safe-area و احترام به کاهش حرکت.

## وضعیت تست و تحویل

`npm run qa` روی نسخه کامل: ۷۱ تست گروه backend (شامل ۶ تست جدید مرحله ۱۲)، ۲۰ تست Demo/API/export، مجموع ۹۱ موفق؛ Static Audit صفر خطا و صفر هشدار. سه سناریوی جدید Chromium و توسعه ماتریس چهار زبان × پنج عرض × شش صفحه در `qa/admin-browser.test.cjs` آماده CI هستند. تلاش محلی Chromium با ERR_BLOCKED_BY_ADMINISTRATOR متوقف شد (HTTP سرور پیش‌نمایش 200). این سناریوهای مرورگری هنوز اجرا نشده‌اند و طراحی ظاهری تأیید نشده است.

## ادامه

مرحله ۱۲.۲: ممیزی جامع فرم‌ها و تنظیمات، بهبود بصری داشبورد و صفحه محصولات و دسته‌بندی براساس اسکرین‌شات مرورگر، حفاظت از پیش‌نویس فرم‌ها، بررسی مرزهای داده و نقش‌ها، و طراحی قرارداد معتبر برای تاریخچه پرداخت/نظرات/کمپین‌ها و پیامک. برای ارسال واقعی پیامک، اطلاعات هویتی مشتریان و تخفیف معتبر، Backend، رضایت دریافت پیام، لغو عضویت، مجوز، جلوگیری از اجرای دوباره و ثبت وقایع لازم است. هیچ تغییر دیتابیس یا سرویس خارجی در این مرحله مجاز/انجام نشده است. سپس مرحله ۱۳: ادغام و تست Customer/Admin روی شاخه مستقل با GitHub Actions پیش از هر انتشار.
