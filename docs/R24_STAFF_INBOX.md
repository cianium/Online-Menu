# R24.5 — Demo staff inbox
Adds a native admin page and sidebar entry; the existing five-item mobile bottom navigation remains unchanged. Mobile inbox uses list/detail with a Back control. Existing demo sign-in, branch scope and app inert gate are checked before each read or mutation. This is not real staff authorization, and live/public admin receives an unavailable notice.
The sample manager can assign to a fixed three-person synthetic roster, respond, resolve, reopen or close. Actual employee directory and roles are deferred. The inbox shows only guest pseudonyms, no phone numbers. Search covers conversation ID, last message and assignee ID; full-text history search is deferred. Guest unread count is cumulative guest message count minus a per-branch, per-tab read marker, marked when the selected conversation is visible; it is not a delivery receipt. Same-origin storage notifications are hints; polling provides fallback.
All messages are rendered as text. The current branch is derived from the existing branch model. Mutations use current version and existing transactional adapter; stale writes are reported. No backend or deployment changes. Full browser and CI verification required before release.

Browser regression scenario added for guest send, unread count, plain-text rendering, staff assignment/reply, resolution/reopen, mobile list/detail and search. Execution is required; source syntax and pure domain checks are not browser evidence. Refreshes are invalidated when a mutation starts to prevent stale reads overwriting the new conversation version.
