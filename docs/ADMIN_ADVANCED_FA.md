# تکمیل پنل مدیریت — Admin Advanced Polish (مرحله ۱۲)

مبنا: آرشیو `Online-Menu-admin-stage12.zip` (نسخه مرحله قبل با ۲۱۱ فایل). اصلاحات روی کپی محلی انجام شده‌اند؛ نه روی `main`، `pages-demo`، PRهای GitHub یا سرور.

## یافته‌ها و اصلاحات

- امتیاز عددی سابق، شناسه ارسال مستقل نداشت. مدل مشترک `js/demo-review.js` اکنون یک نظر آزمایشی به‌ازای هر مرورگر/رستوران با شناسه، امتیاز ۱ تا ۵، متن اختیاری تا ۵۰۰ نویسه و وضعیت pending/approved/rejected نگه می‌دارد. ارسال مجدد حتی با امتیاز برابر، شناسه تازه و وضعیت pending دارد. تأیید قدیمی بر مبنای عدد به نسخه جدید منتقل نمی‌شود. مقایسه نسخه نمایش‌داده‌شده با داده جاری، از تأیید اشتباه داده تغییرکرده جلوگیری می‌کند؛ localStorage دیتابیس تراکنشی یا قفل چندکاربره نیست. نمایش نظر با textContent و بدون پردازش HTML است. اطلاعات شخصی در Demo وارد نشود.
- فرم تنظیمات به هویت و راه‌های ارتباطی تقسیم شد. خطاهای سفارشی نام/تلفن/URL به‌صورت inline با focus و aria-invalid نشان داده می‌شوند. بازگردانی تغییرات ذخیره‌نشده با تأیید کاربر انجام می‌شود؛ ذخیره موفق فرم را با داده پذیرفته‌شده همگام می‌کند. این تغییر جایگزین RBAC سمت سرور نیست.
- فرم محصول در عرض کافی دو ستون و در موبایل باریک یک ستون دارد؛ خوانایی برچسب‌ها و فشردگی بخش عکس/اقدامات بهبود یافت. منطق CRUD و آپلود تغییر نکرده است.
- باشگاه مشتریان: پیش‌نمایش زنده متن پیامک با شمارش واحدهای UTF-16 منطبق با maxlength مرورگر، قفل کنترل‌های تغییر قانون هنگام ویرایش، تأیید کنارگذاشتن پیش‌نویس، حفظ فرم هنگام تغییر تب و بررسی مجدد نسخه ذخیره قبل از حذف تأییدشده. پیش‌نمایش هزینه/تعداد قطعه SMS نیست. وضعیت اتصال پیامک و لزوم رضایت دریافت، لغو عضویت و حفاظت کلیدهای سرور صریح است. هیچ اعتبارنامه یا شماره مخاطب جدیدی ذخیره و هیچ پیام یا تخفیف واقعی اجرا نمی‌شود.
- داشبورد: تفکیک وضعیت سفارش‌های دریافت‌شده، عدم تبدیل پاسخ نامعتبر API به صفر، پنهان‌کردن داده قدیمی بعد از قطعی، و جلوگیری از اعمال پاسخ دیررس refresh قدیمی. API فعلی حداکثر ۱۰۰ سفارش اخیر را برمی‌گرداند؛ در مرز ۱۰۰ این محدودیت نمایش داده می‌شود. تاریخچه پرداخت معتبر برای نمودار درآمد وجود ندارد؛ از مبلغ سفارش یا داده جعلی نمودار نساختیم.
- امنیت مشتری: `paymentReturn` پارامترهای payment/ref/order را به‌عنوان نتیجه قطعی قبول نمی‌کند. فقط پاسخ موفق JSON از API سفارش، با تطبیق شناسه سفارش جاری و وضعیت پرداخت معتبر می‌تواند موفقیت/شکست را نشان دهد؛ در حالت عدم تأیید پیام خنثی نمایش داده می‌شود. کلید idempotency از روی callback جعلی حذف نمی‌شود. این اصلاح UI و آزمون mock است، نه تأیید پرداخت واقعی.
- کنترل‌ها و پیام‌های جدید fa/en/tr/ar دارند. نسخه cache عمومی به‌روز شد و فایل مدل نظر به PWA اضافه شد؛ بسته خصوصی worker بدون cache را حفظ می‌کند.

## اعتبارسنجی واقعی

- `npm run qa`: ۷۸ تست backend/unit و ۲۰ تست Demo/API/export، مجموع ۹۸ موفق، صفر شکست. Static Audit: صفر خطا و هشدار. هفت تست جدید شامل منطق شناسه نظر، داده قدیمی و خراب، شکست ذخیره‌سازی، خلاصه سفارش، ترجمه/فرم و دو آزمون امنیت نتیجه پرداخت با mock.
- `node --check` سه فایل تست مرورگری: موفق. آزمون‌های مرورگری تنظیمات، پیش‌نمایش پیامک، ثبت نظر و یکپارچگی cross-tab توسعه یافتند. Chromium محلی هنگام بازکردن localhost با `ERR_BLOCKED_BY_ADMINISTRATOR` متوقف شد و Node Playwright نصب نیست؛ موفقیت اجرای سناریوهای مرورگری جدید و ظاهر واقعی ادعا نمی‌شود.
- `npm run demo:export`: ۷۵ فایل عمومی؛ تمام SHA-256ها مطابق‌اند. HTTP منو، مدیریت و مدل نظر: ۲۰۰؛ API و `backend/.env.example`: ۴۰۴.
- PostgreSQL/Deno در محیط محلی در دسترس نیستند. سرویس‌های خارجی و VPS، پرداخت، پیامک، چندکاربره، تاریخچه مالی و سنجش Core Web Vitals تأیید نشده‌اند.
