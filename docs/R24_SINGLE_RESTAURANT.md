# Single restaurant, table-only QR product scope
Demo branch creation, rename, selection, activation and route entry are disabled. Existing primary data and table IDs remain. Historical secondary-location records are retained but not shown in the active workspace or included in new backups; multi-location backup restore is rejected. No destructive migration.
Admin creates uniquely coded tables and generates their QR. Generic QR generation was removed from settings; legacy generic demo entry URLs remain compatible with membership flows. Chat and inbox use the fixed primary scope internally. Connected settings require exactly one configured active location; branch creation is disabled in source. Existing database relationships, signed QR/session and payment paths are retained until a verified migration. No database or deployed Edge Function changes. Browser/CI verification remains required.
