# بررسی سه بسته و اصلاحات 4.9.1

تاریخ: ۲۰۲۶-۱۰-۰۷

## دامنه و نتیجه

فایل‌های دریافتی پروژهٔ منوی رستوران ROMANO هستند، نه کتابخانهٔ آموزشی. ساختار منو حفظ شد و قابلیت آموزشی، پرداخت یا شبکهٔ اجتماعی اضافه نشد. اگر منظور از «منابع» فایل، ویدئو و لینک آموزشی است، مدل محتوای آن باید جداگانه تعیین شود؛ تغییر ماهیت پروژه در این نسخه انجام نشده است.

این نسخه یک مرحلهٔ اصلاح و آماده‌سازی است؛ ادعای رفع تمام باگ‌ها، ممیزی امنیتی جامع، آماده‌بودن قطعی برای فروش یا انتشار واقعی ندارد. گزارش حاضر بر یادداشت‌های تاریخی داخل بسته مقدم است.

## مقایسهٔ فایل‌ها

| بسته | نتیجه |
|---|---|
| 4.7.0 | ساختار اصلی منو، ادمین، چهار زبان، بکاپ، احراز هویت و API سرور؛ آزمون‌های syntax/static و ۲۲ تست موجود موفق شدند. |
| 4.9.0-customer | توسعهٔ محیط ادمین، کنترل کیفیت محتوا، انتخاب و تغییر وضعیت گروهی، مدیریت بهتر شکست ذخیره، جست‌وجو/فیلتر/علاقه‌مندی مشتری، تفکیک دادهٔ سرور و دمو و آزمون‌های مرورگر. مبنای اصلاح انتخاب شد. |
| 4.9.0-customer(1) | SHA-256 و تمام بایت‌ها با بستهٔ دوم یکسان است؛ نسخهٔ مستقل یا جدیدتر نیست. |

۳۸ مسیر فایل بین 4.7.0 و 4.9.0 افزوده یا تغییر کرده‌اند؛ بخشی از آن‌ها مستندات و تصاویر آزمون‌اند. هر سه ZIP باز و مقایسه شدند. چون بستهٔ سوم دقیقاً یکسان است، بازاجرای جداگانهٔ آزمون یک کد یکسان ارزشی اضافه نمی‌کند.

SHA-256 بستهٔ 4.7.0:
`b1f1b11e5e9295efa8e569e17c927e11c81e0348a89d53bf838f30ec5e17fc30`

SHA-256 هر دو بستهٔ 4.9.0:
`bef30d105450a8da8cdf94031bbcf96b6c8d02ec3b27d5f07398a909b0720b72`

## امکانات موجود؛ نیاز به ساخت دوباره ندارند

- صفحهٔ مشتری: دسته‌بندی، کارت محصول، محصول ویژه، جزئیات، جست‌وجو، فیلتر دسته، مرتب‌سازی قیمت، علاقه‌مندی محلی، لینک مستقیم محصول و اطلاعات تماس.
- ادمین: داشبورد، افزودن/ویرایش/حذف محصول و دسته، تصویر، فعال/غیرفعال، رونوشت محصول، تغییر وضعیت گروهی، فیلتر کیفیت محتوا، تنظیمات و بکاپ/بازیابی JSON.
- محافظت UX: هشدار تغییرات ذخیره‌نشده، تأیید حذف، وضعیت ذخیره و حفظ فرم در خطای ذخیره.
- چهار زبان فارسی، انگلیسی، ترکی و عربی؛ تغییر جهت RTL/LTR.
- حالت دمو در مرورگر و مسیر جداگانهٔ سرور؛ کش اخیر منوی عمومی با هشدار آفلاین.
- زیرساخت سرور: PostgreSQL، نشست HttpOnly، CSRF، نقش‌ها و عضویت رستوران، ثبت رویداد و زیرساخت ترجمهٔ خودکار. وجود کد این موارد به معنی آزمون عملی سرور نیست.

## باگ‌های اصلاح‌شده

| ایراد | اصلاح | سطح تأیید |
|---|---|---|
| امتیاز صفر با fallback به پنج ستاره تبدیل می‌شد؛ select قدیمی مقدار عددی سرور را نمی‌پذیرفت | ورودی عددی ۰ تا ۵ با گام ۰٫۱، تبدیل سازگار ستاره‌های قدیمی، صفر برای بدون امتیاز | مرورگر: صفر و ۴٫۵ پس از ویرایش، ذخیره و reload حفظ شدند |
| snapshot برای editor امکان تغییر تنظیمات و حذف را فراهم می‌کرد، در حالی که REST این عملیات را به manager محدود می‌کرد | مقایسهٔ تنظیمات و حذف‌ها در مسیر snapshot؛ editor فقط تنظیمات بدون تغییر را می‌فرستد و آن‌ها را بازنویسی نمی‌کند | ۴ تست سیاست دسترسی؛ اتصال مسیر به سرور بازبینی شد؛ اجرای واقعی DB انجام نشده |
| کوکی CSRF مفقود یا نامعتبر در نشست موجود با هش نشست هماهنگ نمی‌شد | صدور توکن و همگام‌سازی هش نشست؛ no-store برای پاسخ‌های خصوصی | بازبینی کد و syntax؛ آزمون واقعی نشست/DB لازم است |
| شرط صفر دسته مانع ذخیرهٔ تنظیمات رستوران تازه یا حذف آخرین دستهٔ خالی می‌شد | پذیرش منوی واقعاً خالی؛ رد محصول بدون دسته؛ حذف همچنان به manager محدود است | بازبینی کد؛ آزمون DB لازم است |
| ذخیرهٔ بدون تغییر، origin ترجمهٔ خودکار/seed را به manual تبدیل می‌کرد | UPDATE ترجمه فقط در صورت تفاوت واقعی متن اجرا می‌شود | بازبینی SQL و syntax؛ اجرای PostgreSQL لازم است |
| تصویر کش‌نشده در حالت آفلاین می‌توانست پاسخ undefined برگرداند | پاسخ مشخص 503 به‌جای مقدار نامعتبر | تست مستقل service worker |
| ورودی‌ها و کنترل‌های موبایل کوچک و ذخیرهٔ فرم دور از دسترس بودند | ورودی ۱۶px، اهداف لمسی حداقل ۴۴px در کنترل‌های هدف، ذخیره/لغو چسبان در فرم محصول/دسته، safe-area و اسکرول داخلی | آزمون مرورگر ۳۲۰px و بازبینی تصویر |
| placeholder قیمت فارسی در UI انگلیسی باقی می‌ماند | ترجمهٔ placeholder و برچسب‌های جدید | assertion مرورگر برای placeholder انگلیسی |
| امضا در ادمین نبود و متن فارسی امضای مشتری انگلیسی بود | نام و URL موجود Cian Khayat / kiankhayat.me حفظ شد؛ امضای ادمین و ترجمهٔ فارسی اضافه شد | بازبینی HTML و فرهنگ ترجمه؛ مقصد خارجی بررسی نشد |

اصلاح origin ترجمه، ردیف‌هایی را که قبلاً اشتباهاً manual شده‌اند خودکار برنمی‌گرداند؛ باید در DB واقعی با اطلاع از سابقهٔ ویرایش بررسی شوند تا ترجمهٔ انسانی از بین نرود.

## موبایل‌فرست بدون شلوغی

مسیر مشتری همان «جست‌وجو → انتخاب دسته → مشاهدهٔ جزئیات» است. قابلیت‌های مدیریتی در صفحهٔ مشتری نمایش داده نمی‌شوند. فیلترهای پیشرفتهٔ ادمین در موبایل جمع‌شونده‌اند. برای ویرایش، تایپوگرافی ورودی‌ها خواناتر و عمل ذخیره در دسترس شد. پنل یا منوی جدیدی صرفاً برای تزئین اضافه نشده است.

## نیازهای مرحلهٔ بعد، با ترتیب اجرایی

### پیش از فروش یا استفادهٔ واقعی

1. **آزمون سرور با PostgreSQL واقعی:** ورود/خروج، نشست منقضی، بازیابی CSRF، editor/manager/viewer، جداسازی رستوران‌ها، CRUD، منوی خالی، snapshot و آپلود. مسیرهای mock مرورگر جایگزین آن نیستند.
2. **جلوگیری از تداخل ویرایش:** revision/ETag و پاسخ 409 برای تغییرات هم‌زمان؛ فعلاً snapshot کامل ممکن است تغییر ادمین دیگر را بازنویسی کند. قفل تراکنش اضافه‌شده این مشکلِ نسخهٔ قدیمی در مرورگر را حل نمی‌کند.
3. **پشتیبان‌گیری عملیاتی:** بکاپ زمان‌بندی‌شدهٔ DB و رسانه و یک آزمایش بازیابی؛ خروجی JSON در مرورگر کافی نیست.
4. **استقرار:** HTTPS، دامنهٔ واقعی، secrets، تنظیم proxy، log و پایش خطا، محدودیت رسانه و بررسی وابستگی‌ها با lockfile به‌روز.
5. **ترجمهٔ محتوای واقعی:** امکان بازبینی/ویرایش چهار زبان در تب‌های داخل همان فرم؛ هشدار ترجمهٔ ناقص. ترجمهٔ خودکار باید با ارائه‌دهندهٔ واقعی آزمایش شود.
6. **کنترل انتشار ساده:** پیش‌نویس، پیش‌نمایش، انتشار و یک نسخهٔ بازگشت؛ بدون افزودن صفحه‌های غیرضروری به مشتری.
7. **نمایش سطح دسترسی در UI:** غیرفعال/پنهان‌کردن عملیات غیرمجاز برای viewer/editor؛ سرور باید همچنان مرجع مجوز باشد.

| انتخاب ارز و نمایش صحیح قیمت | تنظیمات | مناسب رستوران واقعی؛ انتخاب پیش‌فرض نباید فرضی باشد |

| آمار سادهٔ بازدید و بازشدن آیتم | ادمین | تنها در صورت نیاز کسب‌وکار و با حداقل داده |

### فعلاً اضافه نشود

حساب مشتری، کلاس/آزمون آموزشی، شبکهٔ اجتماعی، چت‌بات، کیف پول، پرداخت و باشگاه امتیازی. این موارد هدف صفحهٔ سادهٔ دسترسی به محتوا را تغییر می‌دهند. علاقه‌مندی فعلی محلی است و ثبت‌نام نیاز ندارد.

اگر محصول واقعاً «صفحهٔ منابع» باشد، فیلدهای نوع منبع، لینک/PDF/ویدئو، سطح و موضوع باید جایگزین فیلدهای غذا/قیمت شوند؛ این یک تصمیم محصول جدا از دیباگ منوی فعلی است.

## تأیید انجام‌شده

- هر دو مبنای متفاوت 4.7.0 و 4.9.0: syntax/static و ۲۲ تست موجود موفق.
- 4.9.1: syntax/static بدون شکست؛ ۲۷ تست Node موفق.
- مشتری: ۱۳ سناریوی مرورگر شامل چهار زبان × عرض‌های ۳۲۰/۳۹۰/۱۴۴۰، جست‌وجو و علاقه‌مندی، جزئیات و Escape، لینک مستقیم، خطا/آفلاین و منوی خالی.
- ادمین: ۱۸ سناریو شامل چهار زبان × سه عرض × چهار صفحه، CRUD، ذخیرهٔ ناموفق، بکاپ ناموفق، تغییر گروهی، امتیاز عددی و فرم موبایل.
- خطای JavaScript مدیریت‌نشده در این سناریوها گزارش نشد. خطاهای ذخیره/شبکهٔ عمدی بخشی از آزمون‌اند، بنابراین «هیچ خطای کنسول» ادعا نمی‌شود.
- ارجاعات محلی HTML، شناسه‌های تکراری و syntax با اسکریپت static بررسی شدند؛ این آزمون معادل بررسی همهٔ لینک‌های اینترنتی نیست.
- تصاویر و JSON نتایج در `docs/qa/` قرار دارند. آزمون‌های ادمین با reduced-motion برای تصاویر پایدار اجرا شدند. آزمون‌ها Chromium هستند و مسیرهای سرور را mock می‌کنند؛ service worker در سناریوهای مشتری غیرفعال است و فقط تست جداگانهٔ محدود خودش را دارد.

انجام نشده: اجرای PostgreSQL و SQL جدید، ترجمهٔ خارجی واقعی، اسکن به‌روز وابستگی‌ها، بررسی تمام منابع خارجی، بار/نفوذ، دستگاه فیزیکی Android/iOS، Safari، screen reader و انتشار آنلاین.

## فایل‌ها و اجرا

اصلاحات روی مبنای 4.9.0 اعمال شد. ساختار کلی صفحه، دادهٔ نمونه، تصاویر، چارچوب Vanilla JS و قابلیت‌های موجود حفظ شدند؛ وابستگی تازه اضافه نشد.

- آزمون پایه: `npm run qa`
- مرورگر: اجرای HTTP محلی، سپس `npm run qa:customer` و `npm run qa:browser`؛ به Playwright/Chromium نیاز دارند.
- مسیر مرورگر سفارشی: `CHROMIUM_EXECUTABLE_PATH`
- گزارش تفاوت فایل‌ها: `docs/qa/changed-files.json`
